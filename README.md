This is a Kotlin Multiplatform project targeting Android, iOS.

Setup is documented in [docs/setup.md](./docs/setup.md).
The order book architecture is documented in [docs/orderbook-architecture.md](./docs/orderbook-architecture.md).

* [/iosApp](./iosApp/iosApp) contains an iOS application. Even if you’re sharing your UI with Compose Multiplatform,
  you need this entry point for your iOS app. This is also where you should add SwiftUI code for your project.

* [/sharedLogic](./sharedLogic/src) is for the code that will be shared between app targets in the project.
  The most important subfolder is [commonMain](./sharedLogic/src/commonMain/kotlin). Keep websocket, parsing,
  aggregation, and platform-neutral state here.

* [/androidApp](./androidApp/src/main/kotlin) contains the Android-specific Compose UI. It consumes
  `sharedLogic` directly; UI is intentionally platform-owned.

### Running the apps

Install local development tools first. See [docs/setup.md](./docs/setup.md) for first-run Homebrew trust and signing setup.

```bash
brew bundle
bundle install
```

Use the run configurations provided by the run widget in your IDE's toolbar. You can also use these commands and options:

- Android app: `./gradlew :androidApp:assembleDebug`
- iOS project: `cd iosApp && tuist generate`
- iOS app: open `iosApp/hyper-fullstack.xcodeproj` or `iosApp/hyper-fullstack.xcworkspace` after generation.

### iOS signing

The iOS project is generated by Tuist and uses manual signing through `fastlane match`.
Copy the Fastlane environment example and fill in your personal Apple account and match repository values:

```bash
cp fastlane/.env.example fastlane/.env
```

Then sync signing assets:

```bash
bundle exec fastlane ios sync_development_signing
bundle exec fastlane ios sync_appstore_signing
```

Tuist references the standard match profile names:

- Debug: `match Development org.coreypett.fullstack.orderbook`
- Release/TestFlight: `match AppStore org.coreypett.fullstack.orderbook`

If the match repository is new, set `MATCH_READONLY=false` once to let match create the certificates/profiles.
After that, switch it back to `true`. A simulator build can be validated without signing:

```bash
JAVA_HOME=/Users/coreypett/Library/Java/JavaVirtualMachines/jbr-17.0.12/Contents/Home \
xcodebuild -project iosApp/hyper-fullstack.xcodeproj \
  -scheme iosApp \
  -configuration Debug \
  -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build/xcode-derived \
  CODE_SIGNING_ALLOWED=NO \
  build
```

Fastlane can run the same simulator validation:

```bash
bundle exec fastlane ios build_simulator
```

### Running tests

Use the run button in your IDE's editor gutter, or run tests using Gradle tasks:

- Android tests: `./gradlew :sharedLogic:testAndroidHostTest`
- iOS tests: `./gradlew :sharedLogic:iosSimulatorArm64Test`
